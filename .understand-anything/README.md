# Athena knowledge graph — standalone dashboard

Self-contained copy of the Understand Anything dashboard. Runs without Claude Code,
without the plugin, and without `npm install`.

## Run it

```bash
cd .understand-anything
node serve.mjs
```

The server prints a URL with a one-time access token:

```
🔑  Dashboard URL: http://127.0.0.1:5173/?token=<generated>
```

Open that URL. The token is required — the data endpoints return 403 without it.
Ctrl+C to stop.

**Requires** Node 18 or newer (`node --version`). Nothing else; the server uses only
Node built-ins and there is no `node_modules`. Everything needed is committed, so a fresh
clone runs the two commands above with no build step.

### Options

| Flag | Default | Purpose |
|---|---|---|
| `--port <n>` | `5173` | Steps forward up to 20 ports if the port is taken. |
| `--token <s>` | random | Fixes the token instead of generating one, so the URL is stable across restarts. |

`PORT`, `UNDERSTAND_ACCESS_TOKEN` and `GRAPH_DIR` work as environment-variable
equivalents.

## What is here

| Path | |
|---|---|
| `knowledge-graph.json` | The graph: 496 nodes, 1332 edges, 10 layers, 14 tour steps. |
| `serve.mjs` | Zero-dependency server — static files plus six data endpoints. |
| `dashboard/` | Prebuilt dashboard UI (~2.5 MB), committed so a clone runs immediately. Generated by `vite build` — do not hand-edit; changes are lost on the next rebuild. |
| `meta.json` | Commit the graph was built from, and when. |
| `fingerprints.json` | Per-file structural hashes, used to detect what changed on re-analysis. |
| `.understandignore` | What was excluded from analysis. |

## Reading source in the dashboard

Clicking a node opens its source, which the server reads live from the repository —
so contents always match your working tree. Two consequences:

- This folder must stay inside the repo. Copied elsewhere, the graph and tour still
  work, but the code viewer returns "File not found".
- Only files that are nodes in the graph are readable. The graph is the allowlist, so
  the endpoint cannot be walked into the rest of the disk — `backend/.env`, the
  excluded `backend/tests/`, and anything outside the project root are all refused.

The server binds to `127.0.0.1`, so it is not reachable from other machines.

The page pulls its webfonts from Google Fonts — the only external request it makes.
Offline it falls back to system fonts and everything else still works.

## Regenerating

**The graph** reflects commit `e2288b9`. To rebuild it after the code moves on, re-run
`/understand` in Claude Code — that overwrites `knowledge-graph.json`, `meta.json` and
`fingerprints.json`. It does not touch `serve.mjs` or `dashboard/`, so the standalone
setup survives a re-analysis and will pick up the new graph on next start.

**The UI** in `dashboard/` is committed, so nobody needs to build it to run the dashboard.
Rebuild only to pick up a newer plugin version, which requires the understand-anything
plugin installed (`/understand` pulls it in). From the repo root:

```bash
PLUGIN=~/.claude/plugins/cache/understand-anything/understand-anything/2.7.4
ROOT=$(git rev-parse --show-toplevel)   # resolve before the cd — the plugin dir is not a repo
(cd "$PLUGIN/packages/dashboard" && npx vite build \
  --outDir "$ROOT/.understand-anything/dashboard" --emptyOutDir)
rm -f "$ROOT/.understand-anything/dashboard/knowledge-graph.json"
```

Adjust `2.7.4` to the installed plugin version. That last line is not optional: the
plugin ships a sample graph of *its own* repo in `public/`, which `vite build` copies into
the output. Left in place it is served instead of Athena's graph, and the dashboard
silently shows the wrong project.
